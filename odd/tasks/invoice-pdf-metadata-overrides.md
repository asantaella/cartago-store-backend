# Invoice PDF Metadata Overrides

## Objective

Align the local `master` branch with `release/1.10.0` and make every PDF generated by `InvoicePdfGeneratorService` use optional billing-address metadata overrides for order taxes and final total.

## Problem and Why

The invoice PDF currently calculates order taxes and total from the order model. Some orders have authoritative decimal amounts in `order.billing_address.metadata.order_taxes_total` and `order.billing_address.metadata.order_total`; the generated PDF should use them when valid without changing unrelated invoice details.

## Scope

- Fast-forward local `master` to the local `release/1.10.0` commit; leave the checkout on a feature branch based on that commit.
- Apply the overrides in the shared PDF generator, so store, admin, download, and notification PDF callers all receive the same values.
- Keep the existing EUR symbol and all non-aggregate invoice lines unchanged.
- Add focused regression coverage through the public `InvoicePdfGeneratorService.generateInvoice` method, mocking order retrieval and `pdfmake` to assert the summary amounts passed to the renderer without adding a PDF parser.

## Constraints and Accepted Decisions

- Do not update or contact the remote branch.
- Preserve `.codegraph/` index data; only its `.gitignore` was temporarily moved to allow the requested fast-forward, then replaced with the byte-identical tracked version from `release/1.10.0`.
- Metadata values are decimal `number`s in display units; do not divide them by 100.
- Treat `0` as an explicit override. Missing or `null` values fall back independently to the existing calculation.
- If an override is present but is not a finite number, fail PDF generation with a clear error rather than silently issuing a PDF with a different amount.
- `order_total` is the final order total, including discounts, taxes, and shipping. `order_taxes_total` includes all order taxes, including shipping taxes.
- Format both taxes and total to exactly two decimals.
- Replace only these two aggregate summary amounts. Leave item, shipping, and discount breakdowns unchanged, even if the displayed aggregates do not reconcile with them.
- Keep the PDF's existing hard-coded EUR currency presentation; currency changes are out of scope.
- Receipt-driven development is disabled by clone-local setting; use ordinary verification and do not start native review.
