# Invoice PDF Metadata Overrides

## Objective

Align the local `master` branch with `release/1.10.0` and make every PDF generated by `InvoicePdfGeneratorService` use optional address metadata overrides for order taxes, final total, and the country label.

## Problem and Why

The invoice PDF currently calculates order taxes and total from the order model. Some orders have authoritative decimal amounts in `order.billing_address.metadata.order_taxes_total` and `order.billing_address.metadata.order_total`; the generated PDF should use them when valid without changing unrelated invoice details. Some orders also need the PDF's billing-country label to use the country code stored in the selected address's metadata instead of its standard address field.

## Scope

- Fast-forward local `master` to the local `release/1.10.0` commit; implement on a feature branch based on that commit, then return the checkout to `master` after verification as requested.
- Apply the overrides in the shared PDF generator, so store, admin, download, and notification PDF callers all receive the same values.
- For the country label rendered in the PDF, prefer `billing_address.metadata.country_code` when a billing address exists; when the PDF falls back to the shipping address, prefer `shipping_address.metadata.country_code`.
- Keep the country-code override scoped to invoice PDFs; preserve the existing behavior of other `OrderInvoice` consumers when they do not pass an override.
- Keep the existing EUR symbol and all non-aggregate invoice lines unchanged.
- Add focused regression coverage through the public `InvoicePdfGeneratorService.generateInvoice` method, mocking order retrieval and `pdfmake` to assert the summary amounts and customer address passed to the renderer without adding a PDF parser.

## Constraints and Accepted Decisions

- Do not update or contact the remote branch.
- Preserve `.codegraph/` index data; only its `.gitignore` was temporarily moved to allow the requested fast-forward, then replaced with the byte-identical tracked version from `release/1.10.0`.
- Metadata values are decimal numbers or complete decimal strings in display units; do not divide them by 100. Convert string values to finite numbers and round to two decimal places before rendering.
- Treat `0` as an explicit override. Missing or `null` values fall back independently to the existing calculation.
- If an override is present but is not a finite number, fail PDF generation with a clear error rather than silently issuing a PDF with a different amount.
- `order_total` is the final order total, including discounts, taxes, and shipping. `order_taxes_total` includes all order taxes, including shipping taxes.
- Format both taxes and total to exactly two decimals.
- Replace only these two aggregate summary amounts. Leave item, shipping, and discount breakdowns unchanged, even if the displayed aggregates do not reconcile with them.
- Keep the PDF's existing hard-coded EUR currency presentation; currency changes are out of scope.
- Receipt-driven development is disabled by clone-local setting; use ordinary verification and do not start native review.
- If a metadata country code is missing, empty, non-string, or does not map to a known country label, retain the standard address country code behavior.

## Acceptance Criteria

- `master` points to the same local commit as `release/1.10.0`; the remote remains untouched.
- Invoice PDFs use valid metadata overrides independently and preserve existing calculations when metadata is missing or null.
- Explicit zero values are retained; present invalid values fail clearly.
- Tax and total display with exactly two decimals; all other line items and currency display remain unchanged.
- The shared generator behavior is covered for all its callers by testing its public behavior at the agreed seam.
- Invoice PDF country labels prefer the selected address's `metadata.country_code` over its standard `country_code`; billing is selected when present, otherwise shipping is selected.
- Missing, empty, non-string, or unmapped metadata country codes preserve the existing address-country label.
- Other `OrderInvoice` consumers and unrelated invoice fields retain existing behavior.
